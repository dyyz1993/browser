# M71.1 二进制体积优化报告（boa → optional feature）

> 日期：2026-06-30
> 分支：`feat/m71.1-boa-optional`（worktree: `browser-work-m71.1`，未合入 main）
> 触发：用户问"打包出来多大体积" → M71 分析发现 boa 是强制依赖大头 → 本里程碑落地

---

## 一、核心成果

| 构建配置 | binary 体积 | gzip 体积 | 较 M70 现状 |
|---------|-----------|----------|------------|
| **M70 现状（boa 强制编译）** | 17 MB | 7.7 MB | 基线 |
| **M71.1 默认（无 boa）** | **9.3 MB** | **4.7 MB** | **-45%** 🎉 |
| M71.1 `--features boa`（双引擎） | 17 MB | 7.7 MB | 持平（行为不变） |

**一句话**：纯爬虫用户（从不传 `--js-engine boa`）现在默认少装 7.7MB，gzip 传输从 7.7MB 降到 4.7MB。需要 boa 调试时 `--features boa` 重编，行为完全不变。

---

## 二、为什么能省这么多

### 根因：boa 是单一最大依赖

M70 时 `boa_engine`（git main, 1.0.0-dev）是**非 optional 强制依赖**，即使默认引擎已是 QuickJS（M66 起），boa 全套仍被编进 binary。

实测依赖占比（编译期 rlib）：

| 依赖 | rlib 体积 | M71.1 处理 |
|------|----------|-----------|
| **boa_engine（全套 boa_*）** | **49 MB**（最大） | ✅ 改 optional，默认不编 |
| render（image/png/fontdue） | 11 MB | 保留（截图核心） |
| rquickjs-core（QuickJS 绑定） | 4.3 MB | 保留（默认引擎） |
| gui（winit+softbuffer） | 1.1 MB | 保留（未做 Tier 2） |

binary 内符号证据（M70）：`boa` 335 命中、`tokio` 70、`quickjs` 34。boa 是绝对的体积大头。

### M71.1 的做法：feature 化 + 三层透传

```
cli/Cargo.toml:        default=["quickjs"]   boa = ["browser-js-runtime/boa", "browser-cdp/boa"]
cdp/Cargo.toml:        default=["quickjs"]   boa = ["browser-js-runtime/boa"]
js-runtime/Cargo.toml: boa_engine = optional boa = ["dep:boa_engine"]
```

`#[cfg(feature="boa")]` 门控覆盖：
- **js-runtime**：16 个 boa 专属 shim mod、`trait JsEngine::ctx_mut`、`EngineKind::Boa` 变体、44 个 NativeFn bridge 函数、`install()`/`register_fn*`、timer 后端（TIMER_CALLBACKS/INTERVAL_INFO/drain_due_timer_callbacks）、所有 boa 路径测试模块
- **scripts.rs**：boa import + `execute_scripts*`/`pump_event_loop`/`build_shimmed_context`/`run_scripts_with_base_boa`/`eval_in_tree` boa 分支；`run_scripts_with_base`/`eval_in_tree` 无 boa 时 fallback QuickJS
- **cdp**：`server.rs` match 臂、`runtime_domain.rs`/`server.rs` 测试模块

## 三、QuickJS 路径完整性（关键：不破坏既有能力）

feature 化暴露了一个**既有设计问题**：`render-script` 命令的老入口（`run_scripts`/`run_scripts_with_base`）硬编码 boa 引擎。无 boa 时 fallback QuickJS，暴露 QuickJS 的 9 个 Web API 缺口。

**修复**：全部用纯 JS polyfill 补到 `QUICKJS_*_SHIM`（符合 AGENTS.md 第十一条"纯 JS polyfill 优先，不引 Rust 依赖"）：

| API | 补法 |
|-----|------|
| Event/CustomEvent 构造器 | 强制覆盖（原生 Event 不读 opts.bubbles），加 bubbles/cancelable |
| dataset | Proxy 动态反射 data-* attribute（驼峰↔kebab） |
| tagName | 返回大写（svg → SVG，对齐 W3C） |
| href 属性反射 | a 标签（docsify sidebar sort 依赖） |
| createElementNS | 存 namespaceURI |
| Node 常量 | ELEMENT_NODE/TEXT_NODE 等 |
| Blob/Headers/FormData | 构造器（爬虫够用版） |
| TextEncoder/TextDecoder | UTF-8 伪编码（length 正确） |
| TextEncoderStream/structuredClone | 特性检测 + JSON 深拷贝 |
| location | 重写 `__parseLoc` 正确解析 about:blank（pathname='blank'） |
| history | length 改函数 + pushState/replaceState/back 同步 location |

**验证**：补全后 QuickJS 路径与 boa 路径测试结果一致。

### 4.3 质量对比（关键：砍 boa 零损失）

同站点 QuickJS（9.3M默认）vs boa（17M双引擎）渲染字符数对比：

| 站点 | QuickJS | boa | 一致性 |
|------|---------|-----|--------|
| vuejs.org | 1354 字符 | 1354 字符 | **100%** |
| svelte.dev | 1938 字符 | 1938 字符 | **100%** |

### 4.4 已知限制

- 部分真实站点（如 news.ycombinator.com）`fetch` 失败——**网络/反爬问题**，非渲染问题（本地 fixture 渲染完整）
- react.dev `fetch` 触发 timeout（exit 124）但已渲染 7530 字符且 0 JS 错误——是 30s 超时限制，非崩溃

## 五、体积还能进一步优化吗

已做的（M71.1）= 最大 ROI 项（boa）。剩余可选项（M71 Tier 2/3，未做）：

| 优化 | 收益 | 代价 | 建议 |
|------|------|------|------|
| gui → optional feature | -1~1.5MB | `browser open` 需 `--features gui` | 可做（用户确认 GUI 不急） |
| `lto = "fat"` | -1~2MB | 编译时间 +50% | 不急 |
| image 砍 jpeg 只留 png | -0.5MB | 失去 jpeg 截图 | 不建议 |
| `opt-level = "z"` | -2~4MB | 性能降 20-30% | ❌ 违背 G3 低内存快运行 |

**结论**：默认 9.3MB / gzip 4.7MB 已经是健康水平。要继续砍就走 gui optional（Tier 2），但收益递减。

## 六、如何使用

```bash
# 默认构建（推荐，9.3MB，纯 QuickJS）
cargo build --release -p browser-cli
./target/release/browser fetch https://nuxt.com/ --format markdown

# 需要 boa 引擎调试时（17MB，双引擎）
cargo build --release -p browser-cli --features boa
./target/release/browser fetch https://nuxt.com/ --js-engine boa

# 验证体积
ls -lh target/release/browser
gzip -c target/release/browser | wc -c
```
