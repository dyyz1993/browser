# M95 评估：V8 系引擎实测——宪法 G3 预设被实测数据推翻

> 为宪法级裁决选项 3 提供实测决策数据（对等于选项 2 的 M94 评估）。
> 2026-09-13 实测，本机 macOS arm64 / M2 Max / 32GB。
> 本文仅为评估，不改变宪法现状，不引入任何依赖。

## 一、实测数据（/tmp/v8eval，rusty_v8 0.32.1）

| 指标 | 实测 | 宪法 G3 预设 | 对比 |
|---|---|---|---|
| V8 静态库（构建期） | 48.8 MB | — | 构建产物不入库 |
| **链接后二进制**（hello-world, LTO 前） | **17.6 MB** | "~30MB+" | **推翻**（死代码消除后远小于预设） |
| 我们的 browser（QuickJS） | 10.3 MB | — | 差距仅 **+7.3 MB** |
| **空载 RSS**（一个 isolate） | **7 MB** | "运行时几百 MB" | **推翻**（空载与 QuickJS 相当） |
| 构建 | 预编译库下载，首次 ~5 分钟 | — | 可接受 |

注：空载 RSS ≠ 真实 SPA 负载（V8 JIT + heap 增长后跑重站点预计 50-150MB，
仍显著低于"几百 MB"预设；且我们已有内存护栏 M-cls 子进程 RLIMIT_AS 可复用）。

## 二、战略价值：三个"天花板"可能一次全消

V8 与 Chrome 同源（同一引擎、同一 Skia、同一 ICU）：

| 当前差异项 | QuickJS 现状 | V8 后端预期 |
|---|---|---|
| etsl=226（引擎级） | 跨引擎 toString 格式差 | **消失**（同源格式） |
| toSourceError（已对齐但靠 hack） | Error.toString 正则改写 | **原生一致**（可删 hack） |
| canvasFingerprint（Skia 级） | exact 3.8% | **大概率一致**（同 Skia；仍需实测
  toDataURL 字节，因 Chrome 版本/平台编译差异存在小风险） |

即：**选项 3 若走通，可能同时消解选项 2 的目标**——不只是绕过 Skia 工程，
而是让三个剩余差异中两个直接消失、第三个大概率消失。

## 三、集成成本（诚实估算）

1. **桥层**：js-runtime 150 个 `__*` 桥是 rquickjs 绑定——需写 v8 后端
  （rusty_v8 Function API），量级约 1000-1500 行（参照 qjs_bridge 模式）。
2. **shim 层**：5400 行 JS shim **引擎无关可直接复用**（大优势）。
3. **trait JsEngine 已存在**（QuickJS + boa 双后端）——第三后端架构可行，
   `--js-engine v8` 一个 flag。
4. **宪法**：需 ADR-0006 修订 G3（依据：实测 17.6MB/7MB 推翻原预设；
   可保留"V8 仅可选 feature、默认 QuickJS 保低内存卖点"的折中——
   **默认 QuickJS + `--features v8` 可选**，两全）。
5. **工时估算**：桥层 1-2 周 + 调试对齐 1 周 ≈ **2-4 周**（远低于选项 2 的数月）。

## 四、风险

- xcancel 判定若含 TLS/行为信号（族群评分），V8 引擎不保证过线
 （M94.15 论证）——**建议 V8 后端完成后先本地 fpo 全 diff 再实弹**。
- rusty_v8 上游活跃度一般（deno 团队维护，跟随 V8 LTS）。
- 与宪法 G3 的冲突需要用户明示豁免（本评估不构成豁免）。

## 五、结论

选项 3 的实测代价（+7.3MB 二进制/空载 RSS 持平/2-4 周工时）**显著低于**
宪法预设与选项 2（数月 Skia 工程），且战略上一次消解三个差异项。
推荐形态：**默认 QuickJS 保宪法卖点 + `--features v8` 可选后端**（G3 修订
为"默认路径不引入 V8"而非全面禁止）——但这仍需用户裁决。
