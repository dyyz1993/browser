自写 6 档 HTML（`/tmp/render-matrix/0[1-6]-*.html`），复杂度递进：

## 三、差距清单（按严重度排序）

### 🔴 GAP-1：innerHTML 设置表格片段丢失 td 子节点（严重）

**复现**（最小用例）：
```html
<div id="t"></div>
<script>
  document.getElementById('t').innerHTML =
    '<table><tr><td>A1</td><td>A2</td><td>A3</td></tr></table>';
</script>
```
- **Chrome**: `<table><tbody><tr><td>A1</td><td>A2</td><td>A3</td></tr></tbody></table>`
- **我们**: `<table><tr>A1A2A3</tr></table>` —— **td 元素全丢，文本挤一起**

**影响**：所有用 `element.innerHTML = '<table>...'` 或含 td/tr/li 的 CSR 页面，
爬取时表格结构丢失。这是档位05（超复杂表格）相似度 7% 的根因。

**根因**（已定位）：`crates/js-runtime/src/bridge.rs:2861 qjs_bridge::parse_html`
```rust
pub fn parse_html(target: f64, html: String) {
    let parsed = browser_html_parser::parse(&html);  // html5ever 解析
    let body_id = super::find_first_element(&parsed, "body");
    // ↑ 问题：孤立 <td> 被 html5ever 放进隐式 <table><tbody>
    //   find_first_element("body") 取到 body，children_of(body) 是 <table>
    //   但 copy_subtree 复制 table 时，td 的处理可能丢了
```
需 debug `copy_subtree` 对 table/tbody/tr/td 的复制逻辑。

**验收命令**：
```bash
# 修复后应输出 3 个独立 td（A1 / A2 / A3 分行或正确嵌套）
browser render-script /tmp/innerhtml-bug.html --width 200
# 档位05 相似度应从 7% 提升到 >80%
python3 /tmp/render-matrix/compare2.py
```

### ⚠️ GAP-2：li 列表项 text 提取挤一行（轻微）

**现象**：档位02 `Alice/Bob/Charlie` 在 `fetch --format text` 输出成 `AliceBobCharlie`（无分隔），
但 DOM 结构正确（3 个独立 li 节点）。

**根因**：`extractor` crate 的 text 格式化器没在 `<li>` 之间加换行/分隔符。
（`render-script` ASCII 模式会加 `•` 符号，但 `fetch --format text` 纯文本模式没有）

**影响**：轻微——结构在，只是 text 格式化读起来挤。
**验收**：档位02 相似度 97% → 100%。

---

### ⚠️ GAP-3：insertAdjacentHTML 用 setAttr 当属性（潜在）

**位置**：`scripts.rs:1942`
```js
Element.prototype.insertAdjacentHTML = function(pos, html) {
    if (pos === 'beforeend' && html) {
        __setAttr(this.__nodeId, 'innerHTML', (...)+html);  // ← 当属性存，没解析
    }
};
```
`insertAdjacentHTML` 应该解析 HTML 成节点并插入，当前实现把它当 innerHTML 属性字符串拼接，
和 GAP-1 同类问题（innerHTML 解析缺陷）。

**影响**：用 `el.insertAdjacentHTML('beforeend', '<li>..')` 的页面会丢失结构。
