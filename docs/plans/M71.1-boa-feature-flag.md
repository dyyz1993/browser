# M71.1 实现计划：boa 引擎 feature 化（从强制依赖 → optional）

> 日期：2026-06-30
> 来源：M71 体积分析的 Tier 1，用户已批准「只做 boa，gui 后面再说」「默认 quickjs+gui，砍 boa」。
> **这是技术方案 + 验收清单，动代码前先过一遍。** 符合 AGENTS.md「先查→测试先行→过门禁」流程。

---

## 一、目标

| 目标 | 验收 |
|------|------|
| boa 从强制依赖降为 optional feature | `cargo build`（无 `--features boa`）不编译 boa |
| 默认构建 = quickjs + gui，砍掉 boa | `default = ["quickjs"]`，产物预期 ~11-13MB |
| `--features boa` 仍可编译出双引擎版本 | 行为与现状一致，868 测试全绿 |
| 不破坏任何现有测试 | `cargo test --workspace` 两种 feature 组合都全绿 |
| 不改变默认用户体验 | `browser fetch` / `browser cdp` 默认仍走 QuickJS |

### 2.2 核心耦合：trait JsEngine

```rust
// engine.rs 现状（问题所在）
pub trait JsEngine {
    fn ctx_mut(&mut self) -> &mut boa_engine::Context;  // ← 强耦合 boa
    ...
}
```

QuickJS 的 `ctx_mut()` 已经 panic（走独立路径），说明这方法**只有 boa 路径真正用**。

### 2.3 引擎分发点（scripts.rs + cdp）

- `scripts.rs:2296` `if engine_name == "quickjs" { QuickJS 路径 } else { boa 路径 }`
- `cdp/runtime_domain.rs` 多处 `EngineKind::Boa` / `::QuickJs` 分支

## 三、重构方案（最小侵入）

### 核心思路

把 boa 相关全部用 `#[cfg(feature = "boa")]` 门控。trait 签名拆分：

```rust
// 新方案
pub trait JsEngine: Any {
    fn name(&self) -> &'static str;
    fn as_any(&self) -> &dyn Any;
    fn as_any_mut(&mut self) -> &mut dyn Any;
    fn supports_esm(&self) -> bool { false }
    // ctx_mut() 移到 boa-only 的子 trait，或用 cfg 门控默认方法
    #[cfg(feature = "boa")]
    fn ctx_mut(&mut self) -> &mut boa_engine::Context;
}
```

### 改动清单（按文件）

| 文件 | 改动 | 风险 |
|------|------|------|
| `js-runtime/Cargo.toml` | `boa_engine` 加 `optional=true`；`features.boa = ["dep:boa_engine"]` | 🟢 低 |
| `js-runtime/src/lib.rs` | boa 专属 mod 全部 `#[cfg(feature="boa")]` | 🟢 低 |
| `js-runtime/src/engine.rs` | trait `ctx_mut` cfg 门控；`EngineKind::Boa` 变体 cfg 门控；`create()` 的 boa 分支 cfg | 🟡 中 |
| `js-runtime/src/engine_boa.rs` | 整文件 `#![cfg(feature="boa")]` | 🟢 低 |
| `js-runtime/src/{runtime,esm_loader,*_shim}.rs`（15个） | 整文件 cfg 门控 | 🟢 低 |
| `js-runtime/src/scripts.rs` | boa import + boa 分支 cfg 门控；QuickJS 分支独立可用 | 🟡 中 |
| `js-runtime/src/bridge.rs` | boa 主干 import cfg 门控；`qjs_bridge` mod 不动 | 🟡 中 |
| `cli/Cargo.toml` | 新增 `boa = ["browser-js-runtime/boa"]` feature；`default=["quickjs"]` 不变 | 🟢 低 |
| `cdp/src/runtime_domain.rs` | `EngineKind::Boa` 分支 cfg 门控 | 🟡 中 |
| `cdp/src/server.rs` | boa fallback cfg 门控 | 🟢 低 |

## 四、执行步骤（每步独立 commit + 验收）

> 每步必须：`cargo build` 无 `--features boa` 能过 → `cargo build --features boa` 也能过 → 相关测试绿。

### Step 1：Cargo.toml feature 声明（基础设施）
- `js-runtime/Cargo.toml`：`boa_engine` 改 optional + 加 `boa` feature
- `cli/Cargo.toml`：加 `boa` feature 透传
- **验收**：`cargo build -p browser-js-runtime`（默认）报"找不到 boa"——这是预期的，下一步修
- **commit**：`refactor(js-runtime): M71.1 add boa feature flag (not yet wired)`

### Step 2：lib.rs + boa 专属文件 cfg 门控
- `lib.rs`：16 个 boa 专属 mod 加 `#[cfg(feature="boa")]`
- 整文件门控的 15 个文件加 `#![cfg(feature="boa")]`（或保留文件，门控 mod）
- **验收**：`cargo build -p browser-js-runtime`（默认）通过；`--features boa` 也通过
- **commit**：`refactor(js-runtime): M71.1 cfg-gate boa-only modules`

### Step 3：engine.rs trait + EngineKind 重构
- trait `ctx_mut` cfg 门控
- `EngineKind::Boa` 变体 cfg 门控（无 boa 时 enum 只有 `QuickJs`）
- `parse_str`/`create` 的 boa 分支 cfg 门控
- **验收**：两种 feature 组合 `cargo build --workspace` 通过
- **commit**：`refactor(js-runtime): M71.1 decouple JsEngine trait from boa`

### Step 4：scripts.rs + bridge.rs + cdp 分发点
- scripts.rs 的 boa import/分支 cfg 门控
- bridge.rs boa 主干 cfg 门控（qjs_bridge 不动）
- cdp runtime_domain/server 的 boa 分支 cfg 门控
- **验收**：`cargo test --workspace`（默认）全绿；`--features boa` 全绿
- **commit**：`refactor(js-runtime,cdp): M71.1 cfg-gate boa dispatch paths`

### Step 5：体积验证 + 文档
- 对比 `cargo build --release` 默认 vs `--features boa` 体积
- 更新 AGENTS.md（boa feature 化后的编译说明）+ PROGRESS.md
- **验收**：默认产物 < 15MB；`--features boa` ≈ 17MB（现状）
- **commit**：`docs: M71.1 boa feature 化完成，记录体积对比`

## 五、风险与回退

| 风险 | 缓解 |
|------|------|
| 868 测试中有的隐式依赖 boa | Step 4 若红了，先定位是哪个测试，逐个修；不行就 `git revert` 到 Step 3 |
| trait object 跨 cfg 边界 | ctx_mut 移到 cfg 门控方法，调用点（scripts.rs boa 分支）也 cfg 门控，一致 |
| cdp 测试用 EngineKind::Boa | Step 4 cfg 门控 cdp 测试的 boa 分支，或加 `#[cfg(feature="boa")]` |
| QuickJS 路径被误伤 | 每步先保证默认（quickjs）路径绿，再保证 boa 路径绿 |

**回退策略**：任何一步搞不定，`git revert` 该 commit，前面已绿的状态不受影响。
