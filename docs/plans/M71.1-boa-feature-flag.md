### 2.2 核心耦合：trait JsEngine

```rust
// engine.rs 现状（问题所在）
pub trait JsEngine {
    fn ctx_mut(&mut self) -> &mut boa_engine::Context;  // ← 强耦合 boa
    ...
}
```

QuickJS 的 `ctx_mut()` 已经 panic（走独立路径），说明这方法**只有 boa 路径真正用**。

### 2.3 引擎分发点（scripts.rs + cdp）

- `scripts.rs:2296` `if engine_name == "quickjs" { QuickJS 路径 } else { boa 路径 }`
- `cdp/runtime_domain.rs` 多处 `EngineKind::Boa` / `::QuickJs` 分支

## 三、重构方案（最小侵入）

### 核心思路

把 boa 相关全部用 `#[cfg(feature = "boa")]` 门控。trait 签名拆分：

```rust
// 新方案
pub trait JsEngine: Any {
    fn name(&self) -> &'static str;
    fn as_any(&self) -> &dyn Any;
    fn as_any_mut(&mut self) -> &mut dyn Any;
    fn supports_esm(&self) -> bool { false }
    // ctx_mut() 移到 boa-only 的子 trait，或用 cfg 门控默认方法
    #[cfg(feature = "boa")]
    fn ctx_mut(&mut self) -> &mut boa_engine::Context;
}
```

### 改动清单（按文件）

| 文件 | 改动 | 风险 |
|------|------|------|
| `js-runtime/Cargo.toml` | `boa_engine` 加 `optional=true`；`features.boa = ["dep:boa_engine"]` | 🟢 低 |
| `js-runtime/src/lib.rs` | boa 专属 mod 全部 `#[cfg(feature="boa")]` | 🟢 低 |
| `js-runtime/src/engine.rs` | trait `ctx_mut` cfg 门控；`EngineKind::Boa` 变体 cfg 门控；`create()` 的 boa 分支 cfg | 🟡 中 |
| `js-runtime/src/engine_boa.rs` | 整文件 `#![cfg(feature="boa")]` | 🟢 低 |
| `js-runtime/src/{runtime,esm_loader,*_shim}.rs`（15个） | 整文件 cfg 门控 | 🟢 低 |
| `js-runtime/src/scripts.rs` | boa import + boa 分支 cfg 门控；QuickJS 分支独立可用 | 🟡 中 |
| `js-runtime/src/bridge.rs` | boa 主干 import cfg 门控；`qjs_bridge` mod 不动 | 🟡 中 |

## 五、风险与回退

| 风险 | 缓解 |
|------|------|
| 868 测试中有的隐式依赖 boa | Step 4 若红了，先定位是哪个测试，逐个修；不行就 `git revert` 到 Step 3 |

| QuickJS 路径被误伤 | 每步先保证默认（quickjs）路径绿，再保证 boa 路径绿 |

**回退策略**：任何一步搞不定，`git revert` 该 commit，前面已绿的状态不受影响。

### ⚠️ Step 2-4 复杂度警告（实测发现）

原 plan 低估了 `scripts.rs`/`bridge.rs`/`engine.rs` 三个**共用文件**的门控复杂度：
- `scripts.rs:10` 顶部 `use boa_engine::{Context, JsValue, Module, Source};`——整文件可见
- boa 路径函数散布全文件（`wrap_script`, `run_scripts_with_base` 硬编码 `EngineKind::Boa` 等）
- `engine.rs` 的 `trait JsEngine::ctx_mut() -> &mut boa_engine::Context`——trait 签名强耦合

**修正后的 Step 2-4 策略**（subagent 执行指南）：
1. 先把 `trait JsEngine::ctx_mut` 用 `#[cfg(feature="boa")]` 门控（方法级 cfg）
2. `EngineKind::Boa` 变体 cfg 门控（变体级 cfg）
3. scripts.rs 里所有用 `Context`/`JsValue`/`Module`/`Source` 的函数加 `#[cfg(feature="boa")]`
4. bridge.rs 主干的 boa import + boa 函数 cfg 门控（`qjs_bridge` mod 不动）
5. 16 个 boa 专属 shim 文件整文件门控（`lib.rs` mod 声明 + `#![cfg]`）
6. cdp 的 `EngineKind::Boa` 分支 cfg 门控
7. **每个改动后跑** `cargo build --features boa` + `cargo build`（默认）双绿
8. 最终 `cargo test --workspace` + `--features boa` 双绿

**回退保险**：任何一步 default 构建持续红，`git checkout -- .` 回退该步，主线不受影响（Step1 在 stash）。

### 未完成（卡点）：bridge.rs 拆分

**bridge.rs（3091 行）是真正的卡点。** 它同时含共用代码和 boa 专属代码，需要精细拆分：

| 分类 | 内容 | 处理 |
|------|------|------|
| **共用（保留，引擎无关）** | `SharedTree` 类型、`CURRENT_TREE`/`BASE_URL`/`CURRENT_STORAGE`/`CURRENT_NAV`/`CURRENT_COOKIE` thread_local、`with_tree`/`install_shared*`/`ensure_cookie_jar`/`resolve_url`/`current_*`、`CapturedNetworkEvent` + `CAPTURED_NETWORK`、`qjs_bridge` mod | 不动 |
| **boa 专属（需 cfg 门控）** | `use boa_engine::{...}`、`IntervalEntry=(JsObject,...)`、`TIMER_CALLBACKS`（存 boa JsObject）、`TIMER_WHEEL`（部分）、所有 `NativeFn` bridge 函数（`install()`、`set_body`/`append_body`/`log_fn`/`fetch_set_body`/`create_el`/`set_attr`/`qs`/`storage_*`/`history_*`/`location_*`/`set_timeout_bridge` 等 ~60 个）、`fetch_sync`（boa 版） | `#[cfg(feature="boa")]` 门控 |

**关键依据**（实测）：
- QuickJS 路径（`engine_quickjs.rs` + `scripts.rs` 的 `run_scripts_quickjs`）**只用** bridge.rs 的共用部分（`with_tree`/`install_shared_with_base`/`ensure_cookie_jar`/`qjs_bridge`），**不触碰** boa 的 TIMER_CALLBACKS/NativeFn。
- QuickJS 有自己的 timer 实现（scripts.rs 的 `run_scripts_quickjs` 内部）。
- 下游 cli/cdp 不用 boa 专属重导出（`install_image`/`JsRuntime` 等实测 0 命中）。
