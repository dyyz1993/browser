# M71.3 — Web API 能力差距清单（8 档 vs Chrome baseline）

> **来源**：自写 8 档渐进复杂度 HTML（07-14），每档自带采集 hook
> （console/network/对象属性探针 → 渲染到 `<pre id="out">`），
> 用 Chrome 跑出 baseline，再和我们(QuickJS 9.3M)逐行对比。
>
> **目的**：把"一个个覆盖"落地——每个 MISSING 行 = 一个可独立修复的缺口。
>
> **状态**：差距盘点完成（2026-06-30），待逐个修复。

---

## 一、测试方法（四维采集，公平对比）

每档 HTML 用同一 harness：
```js
var lines = [];
function report(k, v) { lines.push(k + ': ' + v); }
// ... 被测代码 ...
O.textContent = lines.join('\n');  // 结果渲染进 DOM
```

**对比路径**：
- Chrome: `--headless=new --dump-dom` → 提取 `<pre id="out">` 文本 = **baseline**
- 我们: `fetch --format html` → 提取 `<pre id="out">` 文本
- 逐行对比，`MISSING` 行 = 缺口

**四维**：console（探针存在）/ network（fetch/xhr 探测）/ 对象属性（instanceof/typeof）/ HTML（DOM 结构）。
通过 `report()` 统一采集，Chrome 和我们可公平比。

**复现**：
```bash
cd tests/render-matrix
python3 -m http.server 8765 --bind 127.0.0.1 &
python3 chrome_baseline.py          # 生成 baseline/
python3 compare_ours_baseline.py    # 对比 + 缺口汇总
```

## 三、缺口清单（按修复优先级，P0 最影响爬取）

### 🔴 GAP-A：HTMLIFrameElement 未定义（07-iframe 全崩根因，P0）

**现象**：`iframe instanceof HTMLIFrameElement` → `HTMLIFrameElement is not defined`，
导致整段 script 抛错，#out 全空。

**修复**：QuickJS shim 补 `HTMLIFrameElement` 构造器（no-op class，让 instanceof 通过）。
```js
// 加到 QUICKJS_GLOBAL_SHIM
function HTMLIFrameElement() {}
HTMLIFrameElement.prototype = Object.create(Element.prototype);
```

**影响**：所有用 `instanceof HTMLIFrameElement` 的页面（指纹/兼容检测脚本常见）。
**验收**：07-iframe 相似度 0% → >80%。

---

### 🔴 GAP-B：DocumentFragment.childNodes / nodeType 缺失（08-fragment 全崩，P0）

**现象**：`fragment.nodeType` undefined（应=11）、`fragment.childNodes.length` 抛错
（cannot read length of undefined）。

**根因**：QuickJS 的 `createDocumentFragment` 可能返回的对象没实现完整 Node 接口
（缺 nodeType/childNodes）。

**修复**：补 DocumentFragment 的 nodeType=11 + childNodes 数组。
**验收**：08-fragment 相似度 0% → >90%。

---

### 🔴 GAP-C：CSS 选择器全失败（09-css-selectors 全崩，P0）

**现象**：所有 `querySelector` / `querySelectorAll` / `classList` / `matches` / `closest`
返回 undefined/抛错。注意：这些 API 主线肯定有（基础功能），可能是这档页面里
**初始 HTML 的 DOM 解析时机问题**（JS 执行时 #root 内容还没解析进去）。

**待诊断**：先确认是 API 缺失还是 DOM 时序问题（用 render-script 跑静态版本对比）。
**验收**：09-css-selectors 相似度 0% → >85%。

---

### ⚠️ GAP-D：CSS 对象 + getComputedStyle + matchMedia 视口（10-css3，P1）

**缺失**：
- `window.CSS` undefined（应 object，有 `CSS.supports`）
- `CSS.supports('display','flex')` 缺失
- `getComputedStyle` 抛 "not a function"
- `matchMedia('(min-width:100px)').matches` 返回 false（应 true，视口宽度判断错）

**修复**：补 `CSS.supports` 桩 + 修 `getComputedStyle` 注册 + matchMedia 的 matches
按实际渲染宽度计算。
**验收**：10-css3 72% → >90%。

---

### ⚠️ GAP-E：Canvas 2D context 全缺（11-canvas，P1）

**缺失**：`canvas.getContext('2d')` 返回 undefined（应返回 context 对象），
导致所有 ctx.* 方法探测失败、toDataURL 抛错。

**定位**：项目宗旨里 Canvas 像素渲染是 out-of-scope，但 **getContext 必须返回一个
不崩的 stub context**（否则页面能力探测脚本中断）。

**修复**：补 `getContext('2d')` 返回 stub 对象（fillRect/measureText 等方法是 no-op，
measureText.width 返回估算值，toDataURL 返回占位 data URI）。
**验收**：11-canvas 47% → >85%（stub 即可，不要求真渲染）。

---

### ⚠️ GAP-F：WebGL context 全缺（12-webgl，P1）

**缺失**：`canvas.getContext('webgl')` 抛 "not a function"、`WebGL2RenderingContext` undefined。

**定位**：同 GAP-E，WebGL 真渲染 out-of-scope，但 **getContext('webgl') 必须返回 stub**
（或返回 null 但不抛错），否则指纹/能力脚本中断。

**修复**：`getContext('webgl')` 返回 stub gl 对象（getParameter 返回占位字符串，
getSupportedExtensions 返回空数组，createShader 等返回假对象）。
**验收**：12-webgl 26% → >80%。

---

### ⚠️ GAP-G：vdom className 清空 + 事件 dispatch（13-vdom，P2）

**缺失**：
- `app.innerHTML=''; app.appendChild(newNode)` 后 `app.firstChild.className` 为空
  （重建后 className 没反射——可能和 GAP-1 innerHTML 解析同源）
- `new Event('click',{bubbles:true}); el.dispatchEvent(ev)` 后事件没触发
  （dispatchEvent 对合成 Event 不触发监听器）

**验收**：13-vdom 97% → 100%。

---

### ⚠️ GAP-H：performance.navigation + console 扩展方法（14-performance，P2）

**缺失**：
- `performance.navigation` undefined（应 object）
- `console.debug/dir/table` undefined（应 function）
- `navigation entries` 0（应 1）
- `requestIdleCallback` undefined

**修复**：补这几个 no-op 桩。
**验收**：14-performance 95% → 100%。
