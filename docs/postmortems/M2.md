## 关键技术决策（固化）

### D1：手写 CSS 解析器
- 弃用 `cssparser`，自研 ~250 LOC 字符级扫描器
- 理由：M2 只需 flat declarations + tag/class/id，cssparser API 为全 spec 设计，摩擦大于收益
- 代价：未来加伪类 / 属性选择器时要扩 parser，但符合"手写优先"原则

### D2：手写选择器引擎
- 弃用 `selectors` crate，自研 ~250 LOC 匹配器
- 支持：tag / .class / #id / 后代选择器 / 逗号分隔列表
- 不支持：属性选择器、伪类、`>`/`+`/`~` 组合器
- 理由同 D1

### D3：手写布局引擎
- 弃用 `taffy`，自研 block + inline + 折行
- 放弃 float / grid / table / animation
- 理由：学习目的，且 M2/M3/M4 主要场景是爬虫，不需要像素级精确

### D4：BLOCK_TAGS 启发式
- 把 thead/tbody/tr/td/th/caption 加入 block 列表
- HN 用 `<table>` 布局，不这样做会全部 inline 化导致渲染失败
- 妥协：不是真正实现 CSS table model，但对爬虫够用

## 踩坑记录

### 1. `box` 是 Rust 关键字
- **现象：** `mod box;` 报错
- **解决：** 改名为 `boxes.rs`，公共 re-export 保持 `layout::BoxType` 等名字
- **教训：** 选模块名时主动避开 Rust 关键字

### 2. inline layout 的 cursor 传递
- **现象：** M2.6 第一版每个 box 独立处理 cursor，导致 `<span><a>text</a></span>` 这种嵌套只渲染一行
- **解决：** M2.9 重写为 `LayoutState { cursor_x, cursor_y }` 通过可变引用传递，wrapper 递归共享 cursor
- **教训：** 流式布局的 cursor 必须是 share-mutable state，不能每个 box 自管

### 3. anonymous block 混合 inline + block 子节点
- **现象：** HN fixture 中 `<table>` > `<tr>` (Block) > `<td>` (Block) > `<span class="titleline"><a>text</a></span>` (Inline) 这种结构里 anonymous 包装器会混合 Block + Inline
- **解决：** block.rs layout_anonymous_children 加 inline_start 索引，flush inline run 后再 layout block child
- **教训：** CSS 规范的"匿名 block 包装混合内容"是 layout 引擎的核心难点之一，必须支持

### 4. test 期望与 fmt 自动重排冲突
- **现象：** 多行字符串 `"foo\n\` 续行被 rustfmt 吃掉 leading 空白
- **解决：** 改用 `[...].join("\n")` 数组拼接
- **教训：** snapshot 测试用 array join 比 `\` 续行可靠

### 5. e2e test width 设置
- **现象：** HN 标题 "The death of server-side rendering..." 在 80 列下被截断
- **解决：** 标题断言测试用 `--width 400`；custom_width 测试用 60 列验证折行
- **教训：** e2e 测试断言文本完整性时，width 要大于最长一行

## 经验沉淀

### 技术经验
- 流式布局三件套：state object（cursor）+ leaf place 函数 + wrapper 递归
- 渲染管线：HTML → DOM → Layout Tree → 2D char buffer → String
- arena DOM 在 layout 阶段的优势：NodeId 是普通 usize，传给 layout box 当 element_id 很顺手
- CharBuffer 用 `Vec<Vec<char>>` 比 `String` 拼接好——可以 O(1) 写任意 (x, y)，最后再 collapse

### 工程经验
- M2.9 的"修 bug 时发现 M2.6 设计有结构性问题"是正常的——单元测试通过 ≠ 端到端能用
- `cargo clippy --all-targets -- -D warnings` 比 `cargo clippy` 严，因为还会检查 examples / tests
- 当一个 step 的测试卡住时，**写一个 debug example 打印中间结构**比硬看代码快 10 倍

### 流程经验
- "10w 行手写"原则让决策变快——不需要反复权衡"该不该用 crate"
- e2e fixture 用本地合成 HTML（curl 失败时）也能验证管线，比依赖外网更稳
