## 关键技术决策（固化）

### D1：winit + softbuffer 而不是 glutin/wgpu
- **理由：** softbuffer 是跨平台 raw 像素 buffer，无 GPU 依赖；能在 CI / VM / 软件渲染环境跑
- **代价：** 没有硬件加速，渲染慢；但 M5 阶段只画静态文本，性能不是瓶颈
- **何时切 GPU：** M5+ 加滚动 / 视频 / WebGL 时

### D2：手写 5x7 bitmap_font 而不是复用字体库
- **理由：** 5x7 表 ~3KB，覆盖 90 个 ASCII 字符；M5 阶段只需要 ASCII demo
- **代价：** 中文 / Unicode / 抗锯齿都不支持
- **何时切字体库：** M6 cosmic-text（Unicode + 抗锯齿 + 文本布局）或 fontdue（最简）

### D3：tiny-skia 抛弃，直接写 softbuffer
- **现象：** tiny-skia 0.11 Path::new() / Rect::ZERO 等 API 都 break 了
- **决策：** M5.1 目标是"跑通 GUI 工具链"，用 raw 像素写更快
- **何时回来：** M5+ 需要 rounded rect / 抗锯齿线时（URL 栏圆角、按钮）

### D4：`--check` flag 绕开 GUI 在 CI 验证
- **问题：** GUI 窗口创建需要 display server，CI 跑不了
- **方案：** 加 `--check` flag 让 `open` 跑完整管线但不打开窗口，打印渲染文本到 stdout
- **价值：** 7 个 e2e 测试覆盖了 happy path + JS + no-js + 404 + malformed URL + custom width + help

### D5：`render_html_to_string` 重构
- **问题：** M4 `render_html_to_stdout` 把 print! 硬编码进去；M5.2 `open` 要把文本传给 GUI
- **方案：** 抽出 `render_html_to_string` 返回 ASCII text；`render_html_to_stdout` 只是它的 wrapper
- **价值：** 所有渲染子命令共享同一管线

## 踩坑记录

### 1. u32 shift overflow at bit 35
- **现象：** `1u32 << 35` const eval 失败
- **根因：** 5x7 glyph column-major packed 是 35 bits，u32 容纳不下
- **解决：** 改用 u64（35 bits used）
- **教训：** const fn shift 越界在 const eval 阶段就报错，runtime panic 早

### 2. tiny-skia 0.11 API breakage
- **现象：** Path::new() / Rect::ZERO / PremultipliedColorU8::to_bytes 都不存在
- **根因：** tiny-skia 0.11 vs 0.10 API 大改
- **解决：** 直接放弃 tiny-skia，softbuffer raw 像素写
- **教训：** 0.x 版本的小版本号也可能 break API；写代码前看本地 cargo registry 源码

### 3. `Box<dyn Error>` 不能 `?` 转 anyhow
- **现象：** `browser_gui::run_window(config)?` 报 "Send not satisfied"
- **根因：** `Box<dyn Error + 'static>` 默认不带 Send + Sync，但 anyhow::Error 要求都实现
- **解决：** `.map_err(|e| anyhow!("GUI error: {e}"))?`
- **教训：** 错误类型跨 crate 边界时要看 Send + Sync 约束

### 4. winit 0.30 的 `Arc<Window>` 共享
- **现象：** softbuffer Context + Surface 都需要 Arc<Window>，但 Window 字段直接持有 Window 类型
- **解决：** RunningState.window 字段改为 `Arc<Window>`，创建时 Arc::new(window)
- **教训：** softbuffer API 期望 Arc 共享，winit 0.30 默认返回 owned Window

### 5. render_html_to_stdout 重构后函数指针 / 引用反复 edit
- **现象：** M5.2 阶段 edit 多次，render_html_to_string / Cargo.toml browser-gui 依赖反复"没生效"
- **根因：** edit 的 oldText 因为前一次 fmt 重排而不再匹配
- **解决：** Python 强写 / sed 注入
- **教训：** 文件被 fmt 重排后，oldText 要么重新 read，要么用 Python 而不是 edit

## 经验沉淀

### 技术经验
- 跨平台 GUI 最小闭环：winit（窗口） + softbuffer（像素 buffer） + raw 像素写 = 无 GPU 依赖
- 5x7 bitmap_font const fn bit-packer 用 u64（35 bits），column-major 编码
- winit 0.30 的 `ApplicationHandler::resumed` 创建窗口，`WindowEvent::RedrawRequested` 渲染
- 跨 crate 错误类型转换：用 anyhow!() 包装，避免 Box<dyn Error> 的 Send/Sync 不匹配

### 工程经验
- `--check` flag 是 GUI 应用的常见 pattern（macOS headless mode、CI 测试）
- 抽出 string-returning 渲染函数让 stdout / GUI 共享管线
- e2e 用 wiremock + assert_cmd + predicates 三件套覆盖 CLI 全部 flag
- 5x7 glyph 表手写 ~90 个字符是 ~3KB 静态数据，编译时 const 生成

### 流程经验
- M5 把 GUI 切成 4 步：crate 骨架 → 子命令接线 → e2e + headless flag → 收尾
- tiny-skia API break 时果断放弃，不浪费时间对齐小版本
- bitmap_font 用 const fn 编译时生成表，避免运行时 lookup 开销
