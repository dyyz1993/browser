## 关键技术决策（固化）

### D1：M6.0a 折行 — `box.words: Vec<(String, f32, f32)>`
- **现象：** M5 之前 layout 的 `inline.rs` 已经做了换行，把每个 word 的 `(x, y)` 算出来了
- **问题：** renderer 没读这些 word 坐标，而是用 `bx.dimensions.x/y`（= 第一个 word 的起点）+ 整段 text 线性画，结果超出 box 边界的部分被裁掉
- **方案：** LayoutBox 加 `words` 字段，inline layout 填充，renderer 优先读 `words` 逐 word 画
- **价值：** M5.1 GUI 用同样路径画字体，bug 一次性修干净

### D2：M6.0b 整 head 子树不渲染
- **现象：** `<title>` 文本出现在 stdout 第一行
- **根因：** M4.1 黑名单只覆盖 script/style/noscript/template
- **方案：** 加 head/meta/link/title 进黑名单 — 整 head 子树一次性不进 layout
- **替代方案：** 只加 title，不动 head — 但 meta/link 也是不该渲染的，干脆一次性根治
- **代价：** 未来如果有 `<noscript>` in head 的 fallback content 会丢；M6 范围内不会触发

### D3：M6.0c `<li>` 前缀注入写在 construct.rs
- **方案：** `inject_li_bullet` 在 construct 阶段递归找第一个 inline text leaf，前缀 `"• "`
- **替代方案：** 写在 renderer — 但 renderer 只看 text，不知道 tag
- **替代方案 2：** 等 CSS 引擎支持 `::marker` —— 太远，M6 先务实解决
- **副作用：** idempotent（检查 `starts_with("• ")`），多次跑 inject 不会双注入

### D4：M6.0c 段后空行用 margin_bottom heuristic
- **方案：** 每个 block child 在 layout_block_children 里 +1 行空白
- **替代方案：** 只给 `<p>/<h1>/<h2>/<li>` 加 — 但 construct.rs 没把 tag 透传到 LayoutBox（只有 NodeId）
- **代价：** `<div>` 也会有空行，视觉上略浪费但不会出错；M6.1+ computed-styles 接通后再精细化

### D5：M6.0d compare.py 用 macOS qlmanage 当 ground truth
- **理由：** qlmanage 是 macOS 系统级 Quick Look，底层是 WebKit，与 Safari 同源
- **代价：** 只能在 macOS 跑 — 但 PNG 已经 commit 到 git，Linux/Windows 开发者可以直接看
- **替代方案：** 用 headless Chrome — 引入 100MB+ 依赖，违反 L1 自研原则

### D6：M6.1 snapshot test 用文件比对而非 insta
- **理由：** insta 是好 crate，但只是字符串对比；我们已经有 `tests/snapshots/*-ours.txt`，直接读文件比对就行
- **价值：** `UPDATE_SNAPSHOTS=1` env var 一行重生成；mismatch 时写 `*.actual` 文件方便本地 diff

### D7：M6.2 Linux CI 装 X11 dev 包
- **现象：** winit + softbuffer 在 Linux 无头环境编译需要 libxkbcommon / libwayland / libx11 / libxrandr / libxinerama / libxcursor / libxi / libegl-dev
- **方案：** CI yml 加 `apt-get install` step，`if: runner.os == 'Linux'`
- **教训：** 跨平台 GUI 项目第一次过 CI 几乎必然要补 Linux 系统包

## 踩坑记录

### 1. layout words 字段导致 test-constructed LayoutBox 失败
- **现象：** renderer 改成读 `box.words` 后，旧测试构造的 LayoutBox（没填 words）输出全空
- **解决：** renderer 兜底：words 非空走新路径，空则走旧 linear paint
- **教训：** 新字段加在共享 struct 上时，所有读侧都要兜底

### 2. inject_li_bullet 第一次 edit 没生效
- **现象：** edit 报 "成功" 但 grep 找不到函数
- **根因：** 之前用 edit 改了 construct.rs，再 edit 时 cached state 失效（"文件未读取过"）
- **解决：** 改用 Python 脚本强注入
- **教训：** 多次 edit 同一文件出问题时，立刻切到 Python / sed

### 3. `spa_shell_then_set_title_via_script` 旧 e2e 失败
- **现象：** M6.0b 加 head 黑名单后，断言 "Dynamic Title" in stdout 失败
- **根因：** 旧测试断言 `<title>` 文本出现在 body 输出（错的，title 属于 window chrome 不属于 body）
- **解决：** 重命名 `spa_shell_then_set_title_does_not_leak_into_body`，断言反过来 — title 不在 body 出现
- **教训：** 修 bug 时如果旧测试断言反映了 bug 行为，要修测试而不是回退 bug fix

### 4. ROADMAP.md Python replace 失败
- **现象：** 第一次 Python replace 报 "M4/M5 stub not found"
- **根因：** 我把 stub 当多行匹配，但 ROADMAP 末尾没换行，多行字符串末尾的 `\n\n` 匹配不上
- **解决：** 改成 `s.find('## M4')` + slice 截断，再拼接新尾部
- **教训：** 多行 replace 末尾要小心换行符；用 find+slice 更鲁棒

### 5. snapshot test 路径错配
- **现象：** `snapshot_example_width_100` 找不到 `example.com-ours.txt`
- **根因：** compare.py 写的是 `example-ours.txt`，snapshot_pair 拼的是 `example.com-ours.txt`
- **解决：** 把 compare.py 的输出文件名也统一成 `example.com-*`
- **教训：** 文件命名约定要在第一次写就统一，跨工具的命名要对齐

## 经验沉淀

### 技术经验
- **LayoutBox 加字段时 renderer 必须兜底** — 否则旧测试全炸
- **`<head>` 子树不渲染**应该写进 construct 黑名单，不要等 CSS engine
- **`<li>::marker`** 可以用 construct 阶段 text 前缀注入实现，不需要真 CSS pseudo-element
- **`qlmanage`** 是 macOS 上的免费 WebKit ground truth（不需要装 Chrome）
- **Linux winit/softbuffer** 编译需要的 8 个 dev 包固定列表

### 工程经验
- **Snapshot test = bug fix 的安全网** — 修了 bug 之后用 snapshot 把修复 pin 住，下次回退立刻报错
- **UPDATE_SNAPSHOTS=1** 是 Rust 生态的常用 pattern，一行 env var 切换比对/重生成
- **对比图 commit 进 git** — Linux/Windows 开发者没法跑 qlmanage 但能看图
- **跨平台 CI 第一次过**：除了 Rust，还要装系统 GUI dev 包

### 流程经验
- **用户视角的验收** = 用 `Preview.app` 弹出对比图给用户看，不只是跑 cargo test
- **修 bug → 写测试 pin 住** 是黄金组合，缺一不可
- **ROADMAP + postmortem 必须每个 milestone 都更新**，否则下次回来记不清状态
