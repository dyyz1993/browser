fetch --json 诊断数据一览

一条命令打开页面，拿到 console 日志、JS 异常（带调用栈）、网络事件、内容告警——快速校验 SPA 渲染是否有问题。

三种输出形态

普通模式下 stdout 只有页面内容本身，诊断信息走 stderr——两条通道互不污染。需要结构化数据时加 --json；只想看日志错误就再加 --only 投影。

# ① 只要内容（stdout 干净，日志走 stderr） $ browser fetch https://example.com/ --format markdown
# ② 全量信封：内容 + 诊断字段打包成一个 JSON $ browser fetch https://example.com/ --json | jq '{url, title, content, warnings, console, errors, network}'
# ③ 快速诊断：只要日志错误，跳过正文提取（--only 任意逗号组合） $ browser fetch https://example.com/ --json --only console,errors

--json 信封里的 7 个字段

字段类型是什么
console[{level, text}]页面 console.log/info/warn/error/debug 的全部输出。框架内部错误（如 Minified React error #418）通常经 console.error 上报，在这里看。
errors[{message, stack}]未捕获的 JS 异常：顶层 script 抛错、timer/XHR/transition 回调异步抛错，均带调用栈。同一 message 自动去重。
network[{url, method, status, mime_type, body_size}]JS 发起的 fetch/XHR 请求及响应状态——排查"接口 404/被反爬拦了"一眼可见。
warnings[string]内容级告警（反爬壳页 / 空内容等），派生自正文提取。
content{format, text}按 --format 提取的页面正文（markdown/text/html/links…）。
titlestring | null页面 <title>（JS 改过的话是改后的）。
urlstring请求的 URL。

字段按需投影：--only console,errors,network（逗号分隔，任意组合）。不含 content/warnings/title 时会跳过正文提取，输出更干净、跑得更快。

console 和 errors 有什么区别？

console框架/页面主动上报

页面代码调用 console.error/warn/log 打印的内容。React 的 Minified React error #418、ChunkLoadError、业务日志都在这里。

errors未捕获异常

脚本自己崩了没人接：ReferenceError（变量未定义）、timer 回调抛 TypeError、XHR 回调抛错等，带完整调用栈定位到源码行。

校验一个 SPA 是否渲染正常，两个都看：errors 空 + console 无 error 级输出 = 基本健康。

实测：一个"什么都有一点点"的页面

下面是一个真实测试页（本地 HTTP 服务），覆盖了 console 三级日志、顶层异常、异步异常、404 请求、异步渲染。先看页面源码：

<!DOCTYPE html> <html lang="zh-CN"> <head><meta charset="UTF-8"><title>Diagnostics Demo Page</title></head> <body> <div id="app">loading...</div> <nav>Home Docs Blog GitHub</nav> <script> console.log("app bootstrap, version 2.4.1"); console.warn("legacy API deprecated: window.__oldBridge"); // 模拟一个会失败的数据请求（network 事件里能看到 404） fetch("/api/missing-endpoint").then(function(r){ return r.json(); }).catch(function(e){ console.error("api request failed: " + e.message); }); </script> <script> // 顶层同步异常：ReferenceError 中断本段 script var missing = undefinedVar; </script> <script> // 异步异常：timer 回调抛 TypeError（带 stack） setTimeout(function(){ var cfg = null; cfg.timeout = 30; }, 20); // 正常渲染逻辑（不受上面异常影响） setTimeout(function(){ document.getElementById("app").textContent = "Rendered by JS at " + new Date().toISOString().slice(0,10); }, 40); </script> </body> </html>

① 快速诊断：--json --only console,errors

console 三条全收；errors 里两条——顶层 ReferenceError（第 2 段 script 中断）和 timer 回调的 TypeError（带 stack 定位到 6:34 行）。注意第三段 script 的正常渲染没有被前一段异常阻断。

{ "console": [ { "level": "log", "text": "app bootstrap, version 2.4.1" }, { "level": "warn", "text": "legacy API deprecated: window.__oldBridge" }, { "level": "error", "text": "api request failed: unexpected token: '<'" } ], "errors": [ { "message": "Error: undefinedVar is not defined", "stack": "at <eval> (eval_script:1:1)" }, { "message": "cannot set property 'timeout' of null", "stack": " at <anonymous> (eval_script:4:23)\n at <anonymous> (eval_script:752:19)\n at <eval> (eval_script:1:1)\n" } ] }

② console + errors：逐字段看全量输出

console页面 console 输出

三级日志全收，level 字段区分。fetch 失败的业务 catch 里 console.error 的报错也在。

[ { "level": "log", "text": "app bootstrap, version 2.4.1" }, { "level": "warn", "text": "legacy API deprecated: window.__oldBridge" }, { "level": "error", "text": "api request failed: unexpected token: '<'" } ]

errors未捕获异常（同步 + 异步）

第 2 段 script 的 ReferenceError 中断了该段，但第 3 段照常执行；timer 异步 TypeError 的 stack 精确到 demo.html:6:34。

[ { "message": "Error: undefinedVar is not defined", "stack": "at <eval> (eval_script:1:1)" }, { "message": "cannot set property 'timeout' of null", "stack": " at <anonymous> (eval_script:4:23)\n at <anonymous> (eval_script:752:19)\n at <eval> (eval_script:1:1)\n" } ]

networkJS 发起的请求

对 /api/missing-endpoint 的 fetch 返回 404——「接口挂了」这类问题在这直接看到。

[ { "body_size": 460, "method": "GET", "mime_type": "text/html", "status": 404, "url": "http://127.0.0.1:18923/api/missing-endpoint" } ]

warnings内容级告警

派生自正文提取：这个演示页正文很短，触发了「疑似不是真实页面」告警。

[ "content is very short (28 bytes) — likely not the real page" ]

contentJS 渲染后的正文

40ms 后的异步渲染已生效（'Rendered by JS at …'），证明生命线管线（fetch→JS→DOM→提取）通了。

{ "format": "markdown", "text": "Rendered by JS at 2026-09-17" }

③ 完整全量信封（--json 不加 --only）

和 ① 同一次抓取的全量输出——content.text 会把诊断字段"淹没"，这正是 --only 存在的原因。

{ "console": [ { "level": "log", "text": "app bootstrap, version 2.4.1" }, { "level": "warn", "text": "legacy API deprecated: window.__oldBridge" }, { "level": "error", "text": "api request failed: unexpected token: '<'" } ], "content": { "format": "markdown", "text": "Rendered by JS at 2026-09-17" }, "errors": [ { "message": "Error: undefinedVar is not defined", "stack": "at <eval> (eval_script:1:1)" }, { "message": "cannot set property 'timeout' of null", "stack": " at <anonymous> (eval_script:4:23)\n at <anonymous> (eval_script:752:19)\n at <eval> (eval_script:1:1)\n" } ], "network": [ { "body_size": 460, "method": "GET", "mime_type": "text/html", "status": 404, "url": "http://127.0.0.1:18923/api/missing-endpoint" } ], "title": "Diagnostics Demo Page", "url": "http://127.0.0.1:18923/demo.html", "warnings": [ "content is very short (28 bytes) — likely not the real page" ] }

常用校验组合

# SPA 渲染健康检查：无未捕获异常 + console 无 error $ browser fetch https://react.dev/ --json --only console,errors | jq '.errors, [.console[] | select(.level=="error")]' # 接口排查：看 JS 发出的请求都返回了什么状态码 $ browser fetch https://example.com/ --json --only network | jq '.network[] | {status, url}' # 换 boa 引擎对照（默认 QuickJS） $ browser fetch https://example.com/ --json --only console,errors --js-engine boa

能力自 M97.20/M97.21 起内置，双引擎（QuickJS 默认 / --js-engine boa）行为一致。回归测试见仓库 crates/cli/tests/integration_fetch.rs。
